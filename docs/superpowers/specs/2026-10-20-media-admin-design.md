# 媒体与记录管理端

用户已批准 2026-10-20 的桌面效果图并要求直接开发、接入真实数据。

- 同源 Spring Boot 静态网页 `/api/v1/admin/`，复用现有运维口令验证，HTTP-only 会话；口令不保存到浏览器存储。管理员登录后搜索昵称或精确账号 UUID。
- 账号自己发布的记录分页列表，媒体类型、异常类型、展示状态筛选；右侧详情显示逐个媒体的检查、预览和操作。
- 检查真实对象存储，区分原文件/展示图/封面的可用、缺失、未设置、检查失败，网络和权限失败不得认定数据丢失。列表不自动逐文件请求 COS。
- 检查与重建是数据库持久化任务，支持进度、结果、失败重试，刷新页面可以继续查看。重建前重新检查源文件和现有封面，跳过正常封面、原文件缺失、未通过处理或已经删除的媒体。
- 封面生成复用照片派生/视频截帧，采用新的派生文件路径使客户端能识别变化；保留源文件。
- 独立 `admin_hidden` 标记：隐藏后双方的时间线、详情、相册、回顾、相关信笺及新媒体授权均不展示；恢复不改变 status、visibility、couple_id，不触发回收站保留期或再次发布通知。
- 原有签名 URL 的短期有效期无法通过数据库立即撤销；客户端在下一次服务端版本同步后撤下隐藏内容。
- 批量隐藏/恢复带版本，跨账号 ID、过期版本整批拒绝；管理员操作留审计，不向普通用户授予管理权限。
- 页面匹配暖白、莓红效果图，真实数据空状态，移动端可操作。无示例账号或假任务混入正式模式。
- 首版单管理员权限级别、共享运维口令；操作人名称仅用于审计标注。无用户资料编辑、运营大盘和永久删除。

实施判断：复用 Spring Boot、JPA/Flyway、现有 COS SDK，前端原生 HTML/CSS/JavaScript，不新增依赖。生产凭证与发布仍使用项目部署流程；本地测试不读写生产数据。
