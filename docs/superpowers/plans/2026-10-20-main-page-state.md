# 主页状态保留与按变化刷新 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 返回详情、切换主页保留页面状态；首次、实际变化、手动下拉才同步业务数据，未变化图片保持显示。

**Architecture:** 增加仅返回当前用户可见数据版本的轻量接口，不签发媒体地址。前端合并并发同步并按账号隔离；主页检查版本，无变化不设置 loading、不重绘；已有分页、筛选、滚动、相册管理状态保留。头像沿用同一对象的有效地址，账户、关系及授权变化仍清理。

**Tech Stack:** 微信原生 TypeScript；Spring Boot/JPA；现有 Node 和 Maven 测试。

**Spec:** 用户本轮明确的刷新规则，以及 docs/媒体封面与缓存验收.md 中的授权隔离要求。

## Global Constraints

- 不增加依赖，不自动提交或部署；保持原业务入口和权限。
- 另一账号、解绑、会话过期的旧请求不得恢复内容。
- 数据版本不包含签名地址；不能把签名变化当业务变化。
- 首次加载失败可重试，手动下拉强制更新，处理中媒体仍按原有上限更新。

## Review Focus

- 从详情回来，数据无变化时不请求全量接口、不重置分页与图片。
- 两个主页先后进入和并发进入，共用已同步数据且不重复全量请求。
- 另一半新增、删除、改为私密、上传相册、修改资料后，版本能变化。
- 无变化的头像/封面签名不重绑；实际更换图片仍生效。
- 版本检查失败、账号切换、解绑时的错误和旧回调安全。
