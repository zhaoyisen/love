# 备份删除策略与恢复防回退

本文档用于生产上线前的隐私合规检查，重点解决两个问题：

1. 用户删除、解绑、注销后的数据不能因为备份恢复而重新对用户可见。
2. 出现故障需要恢复数据库或对象存储时，必须先验证隐私状态，再对外恢复服务。

## 1. 适用范围

| 数据类型 | 存储位置 | 当前策略 |
|---|---|---|
| 用户、情侣关系、记录、反馈、审计、注销申请 | MySQL | 定时备份，恢复后必须校验 `active_couple_member`、`moment.status`、`deletion_request.status` |
| 登录态、幂等键、限时缓存 | Redis | 不作为长期数据源；故障可重建；不从旧快照恢复已注销用户会话 |
| 图片、视频、缩略图、派生产物 | 腾讯云 COS | 使用私有桶；通过生命周期规则清理临时/派生/已删除对象 |
| 应用日志 | 服务器日志/日志平台 | 保留 request_id 和非敏感上下文，不保存正文、媒体 URL、token、Secret |

## 2. MySQL 备份策略

生产建议：

| 项目 | 建议值 |
|---|---|
| 全量备份 | 每日 1 次 |
| Binlog/增量 | 开启，保留至少 7 天 |
| 备份保留 | 30 天滚动保留；如成本允许，可保留 90 天低频归档 |
| 加密 | 备份文件必须加密存储 |
| 权限 | 仅服务器运维账号和数据库管理员可读 |
| 恢复演练 | 每月至少 1 次在隔离环境恢复 |

恢复前必须执行：

1. 恢复到隔离数据库，不能直接覆盖生产库。
2. 校验已注销用户不再是 `ACTIVE`。
3. 校验已解绑情侣空间没有 active membership。
4. 校验回收站、已清理、已注销数据不会重新出现在时间线和回顾候选中。
5. 校验媒体对象签名接口不会为已删除/已解绑不可见内容签发 URL。

## 3. Redis 策略

Redis 中的数据包括登录 token、刷新 token、幂等键和短期缓存。

生产要求：

- Redis 不作为核心业务数据长期备份源。
- 账号注销时服务端递增 `app_user.session_version`，旧 access token 和 refresh token 即使仍在 Redis 中也会被拒绝。
- 不从 Redis 旧快照恢复 token；故障后允许用户重新登录。
- 如果 Redis 使用持久化，仅用于服务故障恢复，不用于跨天回滚。

## 4. COS 对象存储策略

建议按对象 key 前缀配置生命周期：

| 前缀 | 用途 | 建议清理策略 |
|---|---|---|
| `original/` | 原始上传媒体 | 由业务状态控制删除；不能公开读 |
| `processed/` | 处理后展示媒体 | 删除源记录或注销后进入清理任务 |
| `thumbnail/` | 缩略图 | 跟随源媒体删除 |
| `derivative/` | 模板图、回顾长图等派生产物 | 跟随源记录/回顾版本删除 |
| `tmp/` | 临时文件 | 1 到 3 天自动清理 |

COS 桶必须保持私有读写。小程序只能通过服务端签名 URL 访问，签名前必须重新检查用户权限和资源状态。

## 5. 删除、解绑、注销后的防回退规则

| 场景 | 必须保持的状态 |
|---|---|
| 单方解绑 | `active_couple_member` 不再有双方记录；共同记录不能被对方访问；宠物和回顾不可访问 |
| 记录移入回收站 | `moment.status=TRASHED`；详情、时间线、媒体签名接口均不可访问 |
| 账号注销申请 | `app_user.status=DELETING`；`session_version` 已递增；情侣空间已冻结；有 `deletion_request` 和 `audit_log` |
| 账号删除/匿名化完成 | `app_user.status=DISABLED`；微信身份哈希已断开并替换为不可逆匿名值；`wx_ref_cipher` 清空；昵称替换为“已注销用户”；本人可见/处理中记录正文已擦除并进入回收站；本人媒体对象已调用对象存储删除并标记 `DELETED`；本人派生产物已调用对象存储删除并标记 `DELETED`；本人评论/回应已删除；`deletion_request.status=COMPLETED`，且记录 `processed_derived_assets` |

恢复数据库后，以上状态不能被旧备份覆盖成“可访问”。

## 6. 恢复演练检查清单

每次恢复演练至少抽样验证：

1. 找 1 个已解绑情侣空间，确认双方访问 `/couples/current` 不会恢复配对关系。
2. 找 1 条已移入回收站记录，确认 `/moments/{id}` 不可访问。
3. 找 1 个注销中的用户，确认旧 access token 和 refresh token 无法继续使用。
4. 找 1 个注销申请，确认 `/deletion-requests/{id}/status?token=...` 仍可查看进度。
5. 找 1 个已清理或应清理的媒体对象，确认服务端不会签发可访问 URL。
6. 检查 `audit_log` 中存在解绑、注销、反馈等关键操作记录。

## 7. 当前代码支持情况

已支持：

- `deletion_request`：注销申请和处理状态。
- `audit_log`：隐私关键操作审计。
- `content_feedback`：内容反馈/申诉 case。
- 注销时递增 `session_version`，旧 token 失效。
- 解绑/注销时删除 active membership，停止互访。
- `AccountDeletionProcessingWorker`：生产环境定时处理待注销申请，断开微信身份、禁用旧账号、擦除并下架本人记录、删除本人媒体对象、删除本人派生产物、删除本人评论/回应，并写入完成审计。
- `deletion_request` 进度字段：记录 `processed_moments`、`processed_media_assets`、`processed_comments`、`processed_reactions` 和 `failure_reason`，可通过公开进度 token 查询。
- 内部运维接口：`/internal/feedback`、`/internal/feedback/{id}`、`/internal/deletion-requests/process`、`/internal/deletion-requests/{id}/retry` 均要求 `X-Internal-Operation-Token`，服务端只保存 `INTERNAL_OPERATION_TOKEN_HASH`，用于反馈处理、申诉状态流转、人工触发注销处理和失败重试。

仍需后续补齐：

- 派生产物清理任务进度。
- 注销失败后的可视化人工处理工单/后台。
- 生产环境 MySQL/COS 生命周期配置截图或配置导出。
- 每月恢复演练记录模板和实际演练记录。
