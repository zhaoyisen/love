# 功能缺口与开发优先级清单

本文档用于后续迭代排期、开发和验收。它不是上线操作手册，而是“剩余功能 Backlog + 优先级 + 验收口径”。

当前整理时间：2026-07-10
依据来源：

- `doc/恋爱笔记_微信小程序产品需求文档_PRD_v1.0.docx`
- `doc/恋爱笔记_多端产品_技术详细设计说明书_v1.1.docx`
- 当前代码工作区实现状态

## 维护规则

1. 后续开发优先从本文档的 P0-A 开始，完成后再进入 P0-B、P0-C、P0-D。
2. 每完成一个任务，把“当前状态”改为“已完成”，并在“验收口径”中补充实际验证方式。
3. 如果某项决定延期，必须在“备注”中写清楚延期原因，不能直接删除。
4. P1/P2 不阻塞首版核心闭环，但不能误标为“已完成”。
5. 真机、生产、微信审核相关项目，代码完成后仍应标为“待验收”，直到体验版或生产环境验证通过。

## 状态说明

| 状态 | 含义 |
|---|---|
| 未开始 | 当前代码没有对应功能或只有文档说明 |
| 部分完成 | 已有基础能力，但未达到 PRD/详细设计验收标准 |
| 待真机验收 | 代码已有，必须用微信开发者工具/体验版/真机验证 |
| 待生产验收 | 代码已有，但必须接入真实 MySQL/Redis/COS/微信 AppID/域名验证 |
| 已完成 | 已开发、已测试、验收口径满足 |
| 延期 | 明确不进当前版本，需要记录原因 |

## 优先级说明

| 优先级 | 含义 |
|---|---|
| P0-A | 上线、合规、安全阻断项，最高优先级 |
| P0-B | PRD P0 核心产品功能缺口 |
| P0-C | 详细设计要求的技术、运维、发布门禁缺口 |
| P0-D | 页面和交互补齐项 |
| P1 | MVP 稳定后进入 1.1，不阻塞首版核心闭环 |
| P2 | 后续商业化/差异化探索 |

## 建议开发顺序

后续每轮开发建议按下面顺序推进：

1. P0-A 生产/真机验收：COS 实删、审计抽查、内容安全阻断申诉、解绑通知、备份恢复演练。
2. 图片模板真实生成，并在生成闭环中写入 `derived_asset` 的源媒体、模板 ID、模板版本。
3. 短评删除、提醒设置服务端化、消息聚合。
4. 云宠物完整规则：选择、命名、关系奖励、等级解锁。
5. 年度回顾增强：敏感主动加入、章节、异步任务、版本、分页长图、分享。
6. 视频封面/转码、视频时长校验、弱网与真机验收。
7. Outbox、限流配额、OpenAPI SDK、CI 安全门禁、监控告警、灰度发布。

## 当前最高风险

P0-A 代码阻断项已进入待生产/真机验收；当前最高风险转为以下事项：

- 生产 COS 实删、内容安全阻断申诉、审计日志、备份恢复的真实环境验收；
- 提醒偏好服务端化；
- 图片模板真实生成与 `derived_asset` 生成归属；
- 任务、监控、告警和限流体系。

这些能力建议优先进入下一轮开发。
