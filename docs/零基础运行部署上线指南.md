# 恋爱笔记微信小程序：零基础运行、测试、部署与上线指南

> 如果你的目标是正式上线，不要从本文自行拼装步骤，请直接从第 1 步执行[《生产上线唯一操作手册》](生产上线唯一操作手册.md)。本文保留为本地运行、开发者工具和测试说明。

本文按第一次接触微信小程序的情况编写。请按顺序操作，不要直接跳到“提交审核”。

## 1. 先理解当前项目处于什么阶段

当前目录已经包含一套可以在微信开发者工具中运行的原生小程序客户端：

- 小程序源码：`miniprogram/`
- 微信开发者工具项目配置：`project.config.json`
- TypeScript 检查配置：`tsconfig.json`
- 本地模拟数据：`miniprogram/core/store.ts`
- 模拟接口：`miniprogram/core/mock-api.ts`
- 真实 API 客户端：`miniprogram/services/`
- Java 服务端：`server/`

当前可通过 `miniprogram/core/api-config.ts` 切换模式：

- `useRemoteApi: false`：全部使用本地 mock，适合第一次看页面；
- `useRemoteApi: true`：登录、昵称、邀请、配对、记录、真实 COS 媒体、时间线、删除、恢复、回应、短评、应用内信笺、云宠物和年度回顾使用服务端；
- 年度回顾当前持久化候选、选择、草稿和生成状态；保存到相册时由小程序端 Canvas 生成临时长图，不上传 COS。

因此，核心产品流程已经可做真实双机联调。正式上线前仍需完成真实资源联调、真机验收、隐私/类目/合法域名和审核材料；年度回顾保存长图必须在 iOS/Android 真机上重点验证相册权限和大图导出。

小程序前端代码由微信平台托管。正式上线时不需要自己部署一套静态网页，但必须另行部署真实后端、数据库和私有媒体存储。

## 2. 准备微信账号和小程序账号

### 2.1 只想先在电脑模拟器里看看

可以先使用项目当前的 `touristappid`。它适合本地模拟器体验，但不能作为正式小程序上传和发布。

### 2.2 想真机预览、上传体验版或正式上线

需要先注册正式小程序账号：

1. 打开微信公众平台：<https://mp.weixin.qq.com/>
2. 点击“立即注册”。
3. 选择账号类型“小程序”。
4. 使用未注册过公众平台账号的邮箱完成注册。
5. 按平台提示选择主体类型并完成主体信息、管理员身份和实名认证。
6. 登录小程序后台。
7. 找到“开发管理”或“开发设置”中的 AppID，复制保存。

个人主体和企业主体能使用的服务类目、支付、认证等能力不同。正式运营前应根据实际业务选择主体，不要为了快速测试随意选择错误主体。

如果其他人也要上传代码或真机调试，由管理员在后台“成员管理”中把对方微信号添加为项目成员，并授予开发者权限。仅需要体验的人员添加为体验成员即可。

## 3. 安装微信开发者工具

1. 打开微信官方开发者工具下载页：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>
2. 下载 Windows 稳定版。
3. 完成安装并启动微信开发者工具。
4. 使用微信扫描工具中的二维码登录。
5. 使用的微信号需要是小程序管理员、开发者，或者仅进行游客模式本地调试。

建议使用稳定版。项目使用 TypeScript 编译插件，如果版本过旧，可能无法正确识别 `.ts` 文件。

## 4. 在命令行准备项目

打开 Windows PowerShell，依次执行：

```powershell
cd D:\devlop\love_records
npm install
npm run validate
npm run typecheck
```

预期结果：

- `npm install` 显示依赖安装完成；
- `npm run validate` 显示 19 个页面和 24 个 JSON 文件验证通过；
- `npm run typecheck` 没有红色 TypeScript 错误。

如果 PowerShell 提示禁止运行 `npm.ps1`，改用：

```powershell
npm.cmd install
npm.cmd run validate
npm.cmd run typecheck
```

这里安装的 TypeScript 只用于代码检查。小程序运行时代码没有依赖第三方 npm 包，因此不需要在开发者工具中执行“构建 npm”。

## 5. 微信开发者工具导入本目录

这是最容易选错目录的一步。

1. 打开微信开发者工具。
2. 在启动页点击“+”或“导入项目”。
3. 项目名称填写：`恋爱笔记`。
4. 目录选择：

   ```text
   D:\devlop\love_records
   ```

   必须选择包含 `project.config.json` 的根目录。不要选择 `miniprogram` 子目录。

5. AppID：
   - 只做电脑演示：使用项目配置中的 `touristappid`，或者在工具里选择测试号/游客模式；
   - 需要真机和上传：填写你在公众平台取得的正式 AppID。
6. 后端服务选项选择“不使用云服务”或同义选项。当前项目使用本地 mock，不依赖微信云开发。
7. 点击“导入”。
8. 等待工具完成 TypeScript 编译。
9. 点击顶部“编译”。

正常情况下，模拟器首先显示“把普通日子，慢慢写成我们”的欢迎页。

### 5.1 如果导入后没有显示欢迎页

依次检查：

1. 左侧文件树能否看到 `miniprogram/app.json`。
2. 工具顶部是否有红色编译错误。
3. 项目详情中的“小程序目录”是否识别为 `miniprogram/`。
4. 点击“清缓存”→“清除全部缓存”，再点击“编译”。
5. 确认没有把 `D:\devlop\love_records\miniprogram` 误选成项目根目录。
6. 确认微信开发者工具为较新的稳定版。

## 6. 第一次在模拟器中测试

按下面顺序测试，出现问题时记录页面、操作步骤和控制台错误。

### 流程 A：首次登录和个人记录

1. 勾选用户协议与隐私政策。
2. 点击“微信登录并开始”。
3. 进入“时光”首页。
4. 点击底部中间“记录”。
5. 第一次建议选“文字”，避免模拟器文件选择差异。
6. 输入标题和正文。
7. 选择心情、事件和发生日期。
8. 确认未配对时“与另一半共同可见”不可选择。
9. 进入预览并发布。
10. 返回时光页，确认新记录出现。

### 流程 B：图片和模板

1. 再次进入“记录”。
2. 选择“照片”。
3. 点击“选择照片”，从电脑选一张测试图片。
4. 填写正文后进入“甜蜜图片模板”。
5. 依次切换 6 套模板。
6. 返回记录页，确认模板名称被保存。
7. 预览并发布。

模拟器只能验证大部分界面。相册、相机、授权拒绝、后台切换等行为必须使用真机验证。

### 流程 C：模拟配对

1. 打开底部“我们”。
2. 点击“邀请另一半”。
3. 点击“生成专属邀请”。
4. 点击“模拟 TA 打开邀请”。
5. 阅读共享规则并确认接受。
6. 回到“我们”，确认关系卡和云宠物出现。
7. 回到“时光”，确认共同可见的 TA 记录出现。

注意：这里是单设备模拟，不是真实双账号配对。

### 流程 D：互动、回顾和解绑

1. 打开一条共同可见记录。
2. 切换“心动、抱抱”等回应。
3. 添加一条短评。
4. 打开云宠物，分别执行喂食和玩耍，确认同一动作当天第二次不会重复加成长值。
5. 打开“回顾”，编辑年度候选并查看分享披露清单。
6. 打开“我的”→“默认可见范围”，检查隐私规则。
7. 进入“结束情侣空间”，输入“确认解绑”。
8. 确认解绑后 TA 的记录、宠物和情侣回顾停止访问，而本人记录仍可见。

### 6.1 查看错误的位置

微信开发者工具底部调试器常用面板：

- Console：查看 JavaScript/TypeScript 运行错误；
- Network：接入真实后端后查看 API 请求；
- Storage：查看本地缓存和草稿；
- AppData：查看当前页面 data；
- Wxml：检查页面组件和样式。

测试完成后，可在“我的”底部使用“重置演示数据”，或在开发者工具中清除 Storage，恢复首次进入状态。

## 7. 用正式 AppID 真机预览

### 7.1 替换项目 AppID

打开根目录的 `project.config.json`，把：

```json
"appid": "touristappid"
```

改成：

```json
"appid": "你的小程序正式AppID"
```

不要把 AppSecret 写入任何小程序文件。AppSecret 只能保存在服务端密钥管理系统中。

### 7.2 预览到自己的手机

1. 在开发者工具重新打开或重新编译项目。
2. 确认右上角显示的是正确的小程序账号。
3. 点击顶部“预览”。
4. 工具生成二维码。
5. 使用当前开发者微信扫码。
6. 在手机微信中打开开发版。

如果提示没有权限：

- 检查扫码微信是否已加入项目成员；
- 检查导入时 AppID 是否正确；
- 检查公众平台中的开发者权限是否生效。

### 7.3 真机调试

“预览”适合使用；“真机调试”适合排查问题。

1. 在开发者工具点击“真机调试”。
2. 手机扫码进入调试版本。
3. 测试照片选择、视频选择、相册权限拒绝、网络切换、切后台和系统字体放大。
4. 同时观察电脑端 Console 和 Network。

## 8. 当前版本和真正上线版本的差距

当前已经完成微信会话、昵称、邀请配对、MySQL/Flyway V1–V7、Redis 会话与幂等、真实记录闭环、真实回应与短评、应用内信笺、云宠物、年度回顾状态和客户端长图保存、HMAC 游标、COS STS 直传、文字/图片/视频审核、图片展示图与缩略图、EXIF 清理、30 天回收站清理和 24 小时孤儿上传清理。

正式开放全部页面前仍需完成：

1. 视频封面和转码，或完成支持格式限制及全量真机兼容测试；
2. 注销工单、审计日志与通知任务；
3. 正式 MySQL、Redis、COS 和微信 AppID 的预发布联调；
4. 隐私政策、服务器合法域名、备案、服务类目和审核材料；
5. 生产监控、备份恢复演练和灰度发布。

远端开关位于：

```text
miniprogram/core/api-config.ts
```

本地联调时使用 `http://127.0.0.1:8080/api/v1`；体验版和正式版必须改为备案域名的 HTTPS 地址。

## 9. 后端如何部署

后端位于 `server/`，使用 Java 21 + Spring Boot 3、MySQL 8、Redis 和腾讯云 COS。运行、环境变量、迁移与测试方法见 `server/README.md`，Jenkins 发布细节见 `docs/Jenkins-Docker-Compose服务端部署指南.md`。

生产环境至少需要：

```text
微信小程序
    ↓ HTTPS
API 网关 / WAF
    ↓
Spring Boot API（首发可 1 个实例，稳定后扩容）
    ├── MySQL
    ├── Redis
    ├── 私有对象存储
    └── 内置媒体审核与清理 Worker
```

推荐准备开发、预发布、生产三套环境：

- 开发环境：供日常联调；
- 预发布环境：配置接近生产，用于提审前验证；
- 生产环境：正式用户数据，严格限制访问。

第一次部署请按顺序执行：

1. 给生产 MySQL 做快照，创建 `love_notes` schema 和独立账号；
2. 确认 Redis 仅允许服务器访问；
3. 确认 COS 是私有桶，并已绑定数据万象、完成主账号角色授权；
4. 在 Jenkins 上传 `love-notes-prod-env` Secret file；
5. 推送 `develop`，确认小程序检查、Maven 测试、镜像构建全部通过；
6. 合并到 `main`，由 Jenkins 在 Linux 服务器构建并启动容器；
7. 检查健康接口和 `flyway_schema_history` 已到 V7；
8. 配置 Nginx HTTPS，再把 API/COS 域名加入微信公众平台合法域名；
9. 先上传体验版，完成双账号和真实媒体验收；
10. 验收通过后再提交微信审核。

### 9.1 域名和 HTTPS

真实接口建议使用独立域名，例如：

```text
https://api.example.com/api/v1
```

然后在微信公众平台“开发设置”中配置：

- request 合法域名：API 域名；
- uploadFile 合法域名：对象存储上传域名；
- downloadFile 合法域名：鉴权下载/CDN 域名；
- socket 合法域名：仅在确实使用 WebSocket 时配置。

小程序生产请求必须使用有效 HTTPS 证书。开发者工具中的“不校验合法域名、TLS 版本及 HTTPS 证书”只能用于本地开发，不能解决真机和生产环境问题。参考官方网络说明：<https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html>

### 9.2 不能放进小程序代码的内容

禁止写入前端：

- AppSecret；
- 数据库密码；
- 对象存储永久密钥；
- 内容安全供应商密钥；
- 生产管理员账号；
- 可永久访问用户原图的公开 URL。

## 11. 上传体验版

只有使用正式 AppID，且当前微信号具有开发者权限时才能上传。

1. 先执行：

   ```powershell
   npm run validate
   npm run typecheck
   ```

2. 在微信开发者工具中点击“编译”。
3. 清除缓存后再次执行核心流程。
4. 点击顶部“上传”。
5. 填写版本号，例如 `0.1.0`。
6. 填写项目备注，例如：

   ```text
   首个前端 MVP：记录、配对、时间视图、宠物、年度回顾和解绑。
   ```

7. 上传完成后登录微信公众平台。
8. 进入“版本管理”或“开发管理”。
9. 在开发版本中找到刚上传的版本。
10. 设置为体验版。
11. 添加体验成员，并让体验成员扫描体验二维码。

体验版测试必须使用真实后端测试环境，不能只检查模拟器。

## 12. 提交审核前的资料

至少准备：

- 小程序名称、头像、简介；
- 与实际功能匹配的服务类目；
- 主体认证和管理员信息；
- 平台要求的小程序备案；
- 用户协议；
- 隐私政策和小程序隐私保护指引；
- 收集信息、使用目的、存储期限、删除和注销方式；
- 测试账号或清楚的审核体验路径；
- 可正常访问的生产 API 和合法域名；
- 内容安全、投诉反馈和客服入口；
- 如果使用相册、相机、保存相册、订阅消息，按实际用途完成隐私声明。

备案、认证和服务类目的入口与要求可能随主体和业务变化，以微信公众平台当前后台提示为准，不要照搬旧教程。

## 13. 提交审核和发布

1. 在公众平台“版本管理”中选择已充分测试的开发版本。
2. 点击“提交审核”。
3. 选择正确的服务类目。
4. 填写功能页面、操作说明和审核备注。
5. 如果审核人员需要登录或配对，提供专用审核账号、固定邀请或清晰演示路径。
6. 提交后等待平台审核。
7. 审核驳回时，按驳回原因修复，不要只修改备注后重复提交。
8. 修复后上传更高版本号，重新设置体验版并回归测试。
9. 审核通过后，在版本管理中点击“发布”。
10. 如果后台提供分阶段发布/灰度发布，建议先小比例放量。

发布后马上验证：

- 微信搜索能否找到小程序；
- 首次登录和新建记录是否成功；
- 媒体上传和下载是否正常；
- 真实双账号配对和解绑是否正确；
- 后端错误率、延迟、队列积压和对象存储访问是否正常；
- 隐私政策、客服和注销入口是否可达。

## 14. 推荐的上线节奏

不要从本地 mock 直接跳到全量发布。建议：

1. 本地模拟器：完成所有页面流程；
2. 开发版真机：开发者双账号测试；
3. 体验版：5–10 名体验成员测试 3–7 天；
4. 预发布环境：执行弱网、并发、权限和解绑专项测试；
5. 提交审核；
6. 审核通过后小比例灰度；
7. 指标稳定后再全量；
8. 保留上一个稳定版本和后端回滚方案。

## 15. 你现在最适合执行的下一步

你已经准备好 MySQL、Redis、COS、域名和小程序备案，下一步按这个顺序执行：

1. 在 Jenkins 配置生产 Secret file，但先只构建 `develop`；
2. 用预发布 MySQL/Redis/COS 执行一次部署；
3. 检查 Flyway V1–V7 和 `/actuator/health`；
4. 将小程序 `baseUrl` 改为预发布 HTTPS 域名并上传体验版；
5. 用两个微信账号测试登录、邀请、共享图片、回应、短评、私密隔离、删除恢复和解绑；
6. 验证年度回顾候选、选择、生成状态和保存长图到相册；
7. 完成隐私、合法域名和审核资料后再提交审核。

不要把“容器健康”当成“可以上线”的唯一标准；真实双账号、真实 COS 和真机测试必须全部通过。
