# 恋爱笔记小程序：生产上线唯一操作手册

> 这份文档是唯一需要从头到尾执行的主线。其他三份文档只用于解释某个专题，不再承担“告诉你下一步做什么”的职责。

适用情况：

- 你只有开发环境和生产环境；
- 代码仓库是 `https://github.com/zhaoyisen/love.git`；
- `develop` 是开发分支，`main` 是生产分支；
- 生产后端使用 Ubuntu 24.04、Jenkins、Docker Compose；
- MySQL、Redis 和 COS 使用腾讯云托管服务；
- API 使用 HTTPS 子域名 `love.api.zhaoyisen.com.cn`；
- 小程序前端由微信托管，Java 后端部署到自己的生产服务器。

本文默认路线假设生产服务器使用腾讯云 CVM，MySQL、Redis 使用腾讯云托管服务，并且三者同地域、同 VPC。

如果你使用的是轻量应用服务器，但 MySQL、Redis 也部署在同一台服务器的 Docker 中，可以继续执行本文标注的“单机 Docker 数据库路线”。这条路线不需要填写 MySQL/Redis VPC ID，也不使用腾讯云数据库内网地址；重点改为检查 Docker 网络、数据卷、备份和防火墙。只有当轻量应用服务器要访问腾讯云托管 MySQL/Redis 内网时，才需要先配置云联网或改用 CVM。

## 0. 先理解最终架构

```text
微信小程序（微信托管）
        |
        | HTTPS https://love.api.zhaoyisen.com.cn/api/v1
        v
生产服务器公网 443
        |
      Nginx
        |
        | http://127.0.0.1:8080
        v
Docker 中的 Java API
   |         |          |
   v         v          v
MySQL      Redis      腾讯云 COS + 数据万象
```

Jenkins 也安装在生产服务器，但监听 `8081`，避免和 API 的 `8080` 冲突。

单机 Docker 数据库路线的后端资源关系是：

```text
生产服务器公网 443
        |
      Nginx
        |
        | http://127.0.0.1:8080
        v
Docker 中的 Java API
   |             |
   | Docker 网络 |
   v             v
Docker MySQL   Docker Redis
        |
        v
腾讯云 COS + 数据万象
```

这条路线中，MySQL 和 Redis 不应该向公网开放。即使 MySQL 映射了宿主机端口，例如 `13306:3306`，安全组和系统防火墙也必须禁止公网访问。

你需要完成的顺序只有这一条：

1. 填写上线信息表；
2. 配置 MySQL；
3. 配置 Redis；
4. 配置 COS 和数据万象；
5. 准备生产服务器和安全组；
6. 安装 Docker、Nginx、Jenkins；
7. 解析域名并配置 HTTPS；
8. 创建生产环境变量文件；
9. 配置 Jenkins 凭据和流水线；
10. 推送 `develop` 验证，再合并 `main` 部署；
11. 验证数据库迁移和真实接口；
12. 配置微信服务器域名；
13. 修改小程序生产 API 地址；
14. 上传体验版并真机验收；
15. 提交审核并发布。

任何一步的“验收标准”没有通过，都不要继续下一步。

先复制下面内容到你自己的记事本。真实密码不要发到聊天里，也不要提交 Git。

```text

生产服务器公网 IP：_________________
生产服务器私网 IP：_________________
生产服务器系统：Ubuntu 24.04

MySQL 内网地址：____________________
MySQL 端口：3306
MySQL 宿主机映射端口：______________（单机 Docker 数据库路线填写，例如 13306）
MySQL Docker 容器名：_______________（单机 Docker 数据库路线填写）
MySQL 数据库名：love_notes
MySQL 应用账号：love_notes
MySQL 应用密码：____________________

Redis 内网地址：____________________
Redis 端口：6379 或控制台显示端口
Redis Docker 容器名：_______________（单机 Docker 数据库路线填写）
Redis 用户名：______________________（没有就留空）
Redis 密码：________________________
Redis 是否 TLS：false / true

COS 完整桶名：______________________（必须包含 APPID 后缀）
COS 地域：__________________________（例如 ap-chengdu）
COS 访问域名：______________________
腾讯云 SecretId：___________________
腾讯云 SecretKey：__________________

微信小程序 AppID：__________________
微信小程序 AppSecret：______________
```

### 1.1 怎么找到服务器公网和私网 IP

1. 登录腾讯云控制台；
2. 打开“云服务器 CVM”；
3. 点击生产服务器实例；
4. 在实例详情中记录“公网 IPv4 地址”和“内网 IPv4 地址”。

### 1.2 怎么确认是不是同地域、同 VPC

默认托管数据库路线分别打开 CVM、MySQL、Redis 的详情页，确认：

- 地域相同，例如都在“成都”；
- VPC ID 相同；
- 子网可以不同，但路由必须互通。

如果 VPC ID 不同，不要直接使用公网数据库地址。先在腾讯云完成 VPC 互通，或者把生产服务器迁到相同 VPC。

单机 Docker 数据库路线不需要 MySQL/Redis VPC ID，改为确认：

- MySQL、Redis 容器在生产服务器上运行；
- MySQL 数据目录、Redis 数据目录使用 Docker volume 或明确的宿主机持久化目录；
- MySQL、Redis 没有向公网开放，尤其是 `13306`、`3306`、`6379`；如果你明确接受短期安全风险，可以先记录为待加固项，但正式对外推广前仍建议关闭；
- 如果服务器已有 Jenkins 容器，Jenkins 不能占用公网 `8080`，应改到 `8081` 或只绑定 `127.0.0.1`；
- API 容器能通过 Docker 网络、容器名或 `host.docker.internal` 访问 MySQL/Redis；
- 已经有数据库备份策略，至少在上线前做一次完整备份。

验收标准：上述信息除密码外均已填写。默认托管数据库路线要求 CVM、MySQL、Redis 同地域且网络互通；单机 Docker 数据库路线要求 MySQL/Redis 容器、持久化、备份和访问方式已确认。

## 2. 配置生产 MySQL

如果 MySQL 已经购买，不需要再次购买，只执行创建数据库、创建账号和配置安全组。

如果你走单机 Docker 数据库路线，跳过腾讯云 MySQL 控制台、安全组和 VPC 步骤，直接执行本节最后的“2.5 单机 Docker MySQL 检查和初始化”。

### 2.1 创建数据库

推荐通过腾讯云控制台操作：

1. 登录腾讯云控制台；
2. 打开“云数据库 MySQL”；
3. 点击你的生产实例；
4. 打开“数据库管理”；
5. 点击“创建数据库”；
6. 数据库名填写 `love_notes`；
7. 字符集选择 `utf8mb4`；
8. 排序规则选择 `utf8mb4_0900_ai_ci`；
9. 点击确定。

如果你的控制台没有“创建数据库”，可以进入 DMC 数据库管理工具或使用 MySQL 客户端执行：

```sql
CREATE DATABASE love_notes
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
```

### 2.2 创建应用账号

1. 在 MySQL 实例详情打开“账号管理”；
2. 点击“创建账号”；
3. 账号名填写 `love_notes`；
4. 主机填写生产服务器私网 IP，例如 `10.0.1.8`；
5. 如果必须填写网段，可以填写类似 `10.0.1.%`，不要填写公网 `0.0.0.0/0`；
6. 设置一个至少 16 位的随机密码；
7. 创建后给该账号授权 `love_notes` 数据库；
8. 首次上线需要 Flyway 建表，权限选择“读写 + DDL”，或直接对这一个数据库授予全部权限；
9. 不要给该账号整个 MySQL 实例的全局管理员权限。

如果通过 SQL 创建：

```sql
CREATE USER 'love_notes'@'10.0.1.8' IDENTIFIED BY '请替换成随机强密码';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX, REFERENCES
ON love_notes.* TO 'love_notes'@'10.0.1.8';
FLUSH PRIVILEGES;
```

将示例中的 `10.0.1.8` 换成生产服务器私网 IP。

### 2.3 配置 MySQL 安全组

1. 在 MySQL 实例详情打开“安全组”；
2. 新建或选择一个数据库安全组；
3. 添加入站规则：

```text
协议：TCP
端口：3306
来源：生产服务器私网 IP/32
策略：允许
```

例如服务器私网 IP 是 `10.0.1.8`，来源填写 `10.0.1.8/32`。

不要允许：

```text
0.0.0.0/0:3306
```

### 2.4 记录 JDBC 地址

格式：

```text
jdbc:mysql://MySQL内网地址:3306/love_notes?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC
```

例如：

```text
jdbc:mysql://10.0.2.15:3306/love_notes?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC
```

先记录，后面写入 Jenkins Secret file。

验收标准：数据库 `love_notes` 和账号 `love_notes` 已创建，安全组只允许生产服务器访问。

### 2.5 单机 Docker MySQL 检查和初始化

先在生产服务器查看 MySQL 容器：

```bash
sudo docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
```

确认 MySQL 容器存在，并记录容器名、镜像版本和端口映射。生产环境建议 MySQL 8.x。

检查数据是否持久化：

```bash
sudo docker inspect MySQL容器名 --format '{{json .Mounts}}'
```

输出中必须能看到 volume 或宿主机目录挂载到 MySQL 数据目录，通常是 `/var/lib/mysql`。如果没有持久化挂载，不要继续部署 API，先迁移数据库容器。

进入 MySQL：

```bash
sudo docker exec -it MySQL容器名 mysql -uroot -p
```

创建数据库和应用账号：

```sql
CREATE DATABASE IF NOT EXISTS love_notes
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE USER IF NOT EXISTS 'love_notes'@'%' IDENTIFIED BY '请替换成随机强密码';

GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX, REFERENCES
ON love_notes.* TO 'love_notes'@'%';

FLUSH PRIVILEGES;
```

如果 MySQL 镜像或版本不支持 `utf8mb4_0900_ai_ci`，使用：

```sql
CREATE DATABASE IF NOT EXISTS love_notes
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

API 连接 MySQL 有两种方式：

```text
推荐：API 容器和 MySQL 容器加入同一个 Docker 网络，MYSQL_URL 使用 MySQL 容器名或网络别名。
备选：MySQL 只通过宿主机端口暴露时，MYSQL_URL 使用 host.docker.internal 和宿主机映射端口。
```

同 Docker 网络示例：

```dotenv
MYSQL_URL=jdbc:mysql://mysql:3306/love_notes?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC
MYSQL_USERNAME=love_notes
MYSQL_PASSWORD=你的MySQL强密码
```

宿主机端口示例：

```dotenv
MYSQL_URL=jdbc:mysql://host.docker.internal:13306/love_notes?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC
MYSQL_USERNAME=love_notes
MYSQL_PASSWORD=你的MySQL强密码
```

如果使用 `host.docker.internal`，`docker-compose.yml` 中的 API 服务必须配置：

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

验收标准：`love_notes` 数据库和 `love_notes` 应用账号已创建，MySQL 数据已持久化，公网不能访问 MySQL 端口，API 的 MySQL 连接方式已确定。

如果检查时发现 `love_notes` 数据库已经存在，但 `SELECT user, host FROM mysql.user WHERE user = 'love_notes';` 没有结果，只需要补创建应用账号并授权，不要删除或重建数据库。可以复用 `/data/mysql8/secrets/mysql_app_password.txt` 中的应用密码；如果该文件不存在，再生成一个新的强密码文件。

如果你明确选择让应用直接使用 MySQL `root` 账号，可以跳过创建 `love_notes` 应用账号，但必须记录为临时简化路线。环境变量后续填写：

```dotenv
MYSQL_USERNAME=root
MYSQL_PASSWORD=你的MySQL root密码
```

这能跑通部署，但风险是应用拥有整个 MySQL 实例的管理员权限。后续正式对外推广前，仍建议补建 `love_notes` 应用账号，并把 Jenkins Secret file 中的 `MYSQL_USERNAME/MYSQL_PASSWORD` 改回最小权限账号。

## 3. 配置生产 Redis

Redis 不需要像 MySQL 一样创建表。当前项目使用 Redis DB 0 保存登录会话和幂等键，建议使用独立生产实例。

如果你走单机 Docker 数据库路线，跳过腾讯云 Redis 控制台、安全组和 VPC 步骤，直接执行本节最后的“3.3 单机 Docker Redis 检查”。

### 3.1 检查实例配置

1. 打开腾讯云“分布式缓存数据库 Redis”；
2. 点击生产实例；
3. 确认实例状态为“运行中”；
4. 记录内网地址和端口；
5. 确认已经设置密码，不要开启免密生产访问；
6. 如果控制台显示用户名，记录用户名；默认账号没有用户名时留空；
7. 查看是否启用 TLS，并记录对应端口。

### 3.2 配置 Redis 安全组

1. 在 Redis 实例详情打开“安全组”；
2. 添加入站规则：

```text
协议：TCP
端口：控制台显示的 Redis 端口，通常是 6379
来源：生产服务器私网 IP/32
策略：允许
```

不要向公网开放 Redis。

验收标准：Redis 有密码，安全组只允许生产服务器访问，内网地址和端口已经记录。

### 3.3 单机 Docker Redis 检查

先在生产服务器查看 Redis 容器：

```bash
sudo docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
```

确认 Redis 容器存在，并记录容器名和端口映射。

检查是否设置密码：

```bash
sudo docker exec -it Redis容器名 redis-cli CONFIG GET requirepass
```

如果返回空密码，生产环境建议设置密码，或至少确保 Redis 只在 Docker 内网可访问且没有映射公网端口。

测试连接：

```bash
sudo docker exec -it Redis容器名 redis-cli PING
```

如果设置了密码：

```bash
sudo docker exec -it Redis容器名 redis-cli -a '你的Redis密码' PING
```

预期输出：

```text
PONG
```

如果未带密码执行 `redis-cli PING` 返回：

```text
NOAUTH Authentication required.
```

说明 Redis 已启用密码。不要把密码贴到聊天里。先在 Redis Compose 目录检查密码来源，例如 `/opt/redis/docker-compose.yml`、`/opt/redis/.env` 或 Redis 配置文件。确认密码后，用变量测试：

```bash
REDIS_PW='这里填你的Redis密码，不要发到聊天里'
sudo docker exec redis-server redis-cli -a "$REDIS_PW" PING
```

如果返回 `PONG`，生产环境变量后续填写：

```dotenv
REDIS_HOST=host.docker.internal
REDIS_PORT=6379
REDIS_USERNAME=
REDIS_PASSWORD=你的Redis密码
REDIS_SSL=false
```

如果 Redis 密码已经被贴到聊天、截图、日志或工单中，当前可以先继续部署，但正式发布前建议轮换密码，并同步更新 Jenkins Secret file。

单机 Docker Redis 通常不启用 TLS，因此生产环境变量一般填写：

```dotenv
REDIS_HOST=redis
REDIS_PORT=6379
REDIS_USERNAME=
REDIS_PASSWORD=你的Redis密码
REDIS_SSL=false
```

如果 API 只能通过宿主机端口访问 Redis，则填写：

```dotenv
REDIS_HOST=host.docker.internal
REDIS_PORT=6379
REDIS_USERNAME=
REDIS_PASSWORD=你的Redis密码
REDIS_SSL=false
```

使用 `host.docker.internal` 时，同样需要给 API 服务配置：

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

验收标准：Redis 能返回 `PONG`，密码和访问方式已确认，`REDIS_SSL=false`，公网不能访问 Redis 端口。

## 4. 配置腾讯云 COS 和数据万象

如果 COS 存储桶已经创建，重点检查桶名、地域、私有权限和数据万象绑定。

### 4.1 创建或检查存储桶

1. 打开腾讯云“对象存储 COS”；
2. 进入“存储桶列表”；
3. 如果没有生产桶，点击“创建存储桶”；
4. 名称建议填写 `love-notes-prod`；
5. 地域选择与生产服务器相同或距离最近的地域；
6. 访问权限选择“私有读写”；
7. 存储类型选择“标准存储”；
8. 创建完成后记录完整桶名，例如 `love-notes-prod-1303187601`；
9. 记录地域，例如 `ap-chengdu`；
10. 记录访问域名，例如：

```text
love-notes-prod-1303187601.cos.ap-chengdu.myqcloud.com
```

桶名必须填写控制台显示的完整名称，不能漏掉数字 APPID 后缀。

### 4.2 验证存储桶是私有的

1. 在桶内上传一张没有隐私内容的测试图片；
2. 复制对象 URL；
3. 使用浏览器无痕窗口打开；
4. 应返回 `AccessDenied` 或无权限；
5. 如果可以直接显示图片，立即把桶权限改为“私有读写”。

如果控制台已经明确显示“私有读写”，但你选择跳过未签名 URL 测试，可以先继续部署，并把该项记录为已接受风险。正式发布前仍建议补测一次，避免桶策略、临时授权或对象 ACL 导致文件可被公开访问。

### 4.3 绑定数据万象

项目会调用文字、图片、视频审核，并生成展示图和缩略图，因此必须开通数据万象。

1. 打开腾讯云“数据万象 CI”控制台；
2. 首次进入时按页面提示开通服务；
3. 打开“存储桶管理”或“存储桶绑定”；
4. 选择刚才的生产 COS 桶；
5. 点击绑定或开通；
6. 如果页面要求“服务角色授权”，点击同意授权；
7. 在内容审核中启用图片、视频、文本审核；
8. 保持默认审核策略即可，后续再按业务调整；
9. 确认图片基础处理可用。

### 4.4 获取主账号 API 密钥

你已经明确不想创建子账号，因此这里按主账号密钥配置：

1. 打开腾讯云“访问管理 CAM”；
2. 进入“API 密钥管理”；
3. 创建或查看 `SecretId` 和 `SecretKey`；
4. 立即保存到你自己的密码管理器；
5. 后面只写入 Jenkins Secret file；
6. 禁止写入小程序源码、GitHub、Dockerfile、聊天记录或截图。

主账号密钥一旦泄漏，影响的不只是 COS，而是整个腾讯云账号。代码支持主账号，但这不是低风险方案。

### 4.5 配置费用告警

1. 在腾讯云费用中心创建月预算；
2. 给 COS 外网下行、内容审核和图片处理设置告警；
3. 给 MySQL、Redis 和 CVM 设置余额或到期提醒。

验收标准：桶是私有读写，已绑定数据万象，文字/图片/视频审核可用，完整桶名和地域已记录。

## 5. 准备生产服务器和安全组

推荐最低配置：

```text
系统：Ubuntu 24.04 LTS 64 位
CPU：2 核
内存：4 GB
系统盘：60 GB
公网带宽：至少 3 Mbps
地域和 VPC：与 MySQL、Redis 相同
```

### 5.1 配置 CVM 安全组

生产服务器入站规则只保留：

| 端口 | 来源 | 用途 |
|---|---|---|
| 22 | 你当前电脑的公网 IP/32 | SSH |
| 80 | `0.0.0.0/0` | HTTP 和申请证书 |
| 443 | `0.0.0.0/0` | 小程序 HTTPS API |
| 8081 | 你当前电脑的公网 IP/32 | 初次配置 Jenkins |

不要开放：

- 8080：API 只绑定服务器本机；
- 3306：MySQL 不对公网开放；
- 6379：Redis 不对公网开放。
- 13306：如果 MySQL Docker 映射了这个宿主机端口，也不对公网开放。

如果你的家庭公网 IP 会变化，登录 Jenkins 前再临时更新 8081 的来源 IP，不要为了方便改成 `0.0.0.0/0`。

轻量应用服务器还需要检查“防火墙/安全组”页面：只放行 `22`、`80`、`443`，初次配置 Jenkins 时临时放行 `8081` 给你当前电脑公网 IP。不要放行 `8080`、`13306`、`3306`、`5432`、`6379`。

如果 `sudo ss -lntp` 看到类似下面输出，表示 Docker 已经把端口绑定到所有网卡：

```text
0.0.0.0:8080
0.0.0.0:13306
0.0.0.0:6379
```

这时不能只看 `ufw`。Docker 发布端口会直接写入 iptables，`ufw inactive` 或普通 `ufw deny` 都不能作为唯一防护。必须至少完成其中一种处理：

1. 在轻量应用服务器控制台防火墙中关闭这些端口；
2. 重新创建相关容器，把端口绑定到 `127.0.0.1`，例如 `127.0.0.1:13306:3306`；
3. 更稳妥地让 API、MySQL、Redis 加入同一个 Docker 网络，不对宿主机发布数据库端口。

本项目推荐：Jenkins 使用 `8081`，API 使用 `127.0.0.1:8080`，MySQL/Redis 不对公网发布端口。若你明确接受单机数据库公网端口的短期风险，可以先延期处理 MySQL/Redis/Postgres 端口，但 Jenkins 占用 `8080` 是部署 API 的功能冲突，必须先改。

### 6.4 把 Jenkins 端口改成 8081

Jenkins 默认端口是 8080，但本项目 API 也使用 8080，所以必须改。

执行：

```bash
sudo systemctl edit jenkins
```

编辑器打开后粘贴：

```ini
[Service]
Environment="JENKINS_PORT=8081"
```

保存退出，然后执行：

```bash
sudo systemctl daemon-reload
sudo systemctl enable jenkins
sudo systemctl restart jenkins
sudo systemctl status jenkins --no-pager
```

检查监听端口：

```bash
sudo ss -lntp | grep 8081
```

如果 Jenkins 已经以 Docker 容器运行，并且 `docker ps` 显示 `0.0.0.0:8080->8080/tcp`，先不要部署 API。你需要找到 Jenkins 容器的创建方式：

```bash
sudo docker inspect jenkins --format '{{json .Mounts}}'
sudo docker inspect jenkins --format '{{json .Config.Labels}}'
```

如果它由 Docker Compose 管理，修改对应 compose 文件，把端口改为只给当前电脑访问的 `8081`，例如：

```yaml
ports:
  - "8081:8080"
```

如果只是临时 `docker run` 创建，保留原 Jenkins 数据卷后重新创建容器，并把端口改成：

```text
8081:8080
```

确认 Jenkins 能通过 `http://生产服务器公网IP:8081` 打开后，再释放 `8080` 给 API 使用。不要让 Jenkins 和 API 同时占用宿主机 `8080`。

当前单机 Docker 数据库路线中，如果检查到这些 Compose 标签：

```text
Jenkins compose 文件：/opt/jenkins/compose.yaml
MySQL compose 文件：/data/mysql8/compose.yaml
Redis compose 文件：/opt/redis/docker-compose.yml
```

则按下面目标调整端口：

```text
Jenkins：8081:8080
MySQL：127.0.0.1:13306:3306
Redis：127.0.0.1:6379:6379
```

调整后在各自目录执行 `sudo docker compose up -d`。这些容器已经使用持久化挂载，重建容器不会删除 Jenkins 配置或 MySQL/Redis 数据；但不要执行 `docker compose down -v`，也不要删除 `/var/lib/docker/volumes/jenkins_jenkins_home`、`/data/mysql8` 或 `/opt/redis/data`。

### 6.5 允许 Jenkins 使用 Docker

```bash
sudo usermod -aG docker jenkins
sudo systemctl restart jenkins
```

验证：

```bash
sudo -u jenkins docker version
sudo -u jenkins docker compose version
```

两条命令都必须成功。

如果 Jenkins 以 Docker 容器运行，则改为在 Jenkins 容器内验证流水线依赖：

sudo docker exec jenkins java -version
sudo docker exec jenkins docker version
sudo docker exec jenkins docker compose version

## 8. 解析 API 域名

本项目主域名是 `zhaoyisen.com.cn`，API 域名使用：

```text
love.api.zhaoyisen.com.cn
```

在 DNSPod 管理 `zhaoyisen.com.cn` 时，对应“主机记录”应填写：

```text
love.api
```

如果生产服务器在中国大陆，先在腾讯云备案控制台确认这个域名已经完成 ICP 备案。小程序备案和网站域名 ICP 备案不是同一个检查项；不要等到微信配置服务器域名时才处理。

### 8.1 在 DNSPod 添加 A 记录

1. 登录腾讯云“云解析 DNS”；
2. 进入“权威解析”；
3. 点击你的主域名；
4. 点击“添加记录”；
5. 主机记录填写 `api`；
6. 记录类型选择 `A`；
7. 线路类型选择“默认”；
8. 记录值填写生产服务器公网 IP；
9. TTL 保持默认；
10. 保存。

注意：主机记录填写的是相对当前域名 `zhaoyisen.com.cn` 的前缀。若目标是 `api.zhaoyisen.com.cn`，主机记录填 `api`；若目标是本项目约定的 `love.api.zhaoyisen.com.cn`，主机记录填 `love.api`。不要填写错别字，例如 `loave.api`。

### 8.2 验证 DNS

在 Windows PowerShell 执行：

```powershell
nslookup love.api.zhaoyisen.com.cn
```

返回 IP 必须是生产服务器公网 IP。

如果不是，等待几分钟后重试。DNS 还没生效时不要申请证书。

如果 `nslookup love.api.zhaoyisen.com.cn` 返回 `Non-existent domain`，或服务器执行 `curl -I http://love.api.zhaoyisen.com.cn` 返回 `Could not resolve host`，说明 API 子域名记录还不存在，或者当前域名没有使用你正在配置的 DNS 服务商。先到域名当前权威 DNS 控制台添加对应主机记录的 A 记录，再继续申请 HTTPS 证书。

验收标准：`nslookup` 返回生产服务器公网 IP。

## 9. 配置 Nginx 和 HTTPS

### 9.1 创建 HTTP 反向代理配置

在生产服务器执行：

```bash
sudo tee /etc/nginx/sites-available/love-notes-api > /dev/null <<'EOF'
server {
    listen 80;
    listen [::]:80;
    server_name love.api.zhaoyisen.com.cn;

    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_read_timeout 90s;
    }
}
EOF
```

确认文件中的 `server_name` 是真实 API 域名 `love.api.zhaoyisen.com.cn`：

```bash
sudo nano /etc/nginx/sites-available/love-notes-api
```

启用配置：

```bash
sudo ln -s /etc/nginx/sites-available/love-notes-api /etc/nginx/sites-enabled/love-notes-api
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

此时访问 API 可能返回 502，因为 Java 容器还没部署。这不影响申请证书。

### 9.2 使用 Certbot 申请 HTTPS 证书

安装 Certbot：

```bash
sudo snap install core
sudo snap refresh core
sudo snap install --classic certbot
sudo ln -s /snap/bin/certbot /usr/local/bin/certbot
```

申请并自动修改 Nginx：

```bash
sudo certbot --nginx -d love.api.zhaoyisen.com.cn
```

操作时：

1. 输入接收证书到期通知的邮箱；
2. 同意服务条款；
3. 选择把 HTTP 自动跳转到 HTTPS；
4. 等待显示成功。

测试自动续期：

```bash
sudo certbot renew --dry-run
```

检查 Nginx：

```bash
sudo nginx -t
sudo systemctl status nginx --no-pager
```

如果 Certbot 无法使用，可以在腾讯云 SSL 证书控制台申请证书，下载 Nginx 格式的 `.crt` 和 `.key` 文件，再按腾讯云 Nginx 证书文档手工安装。

如果 Certbot 输出类似下面警告，但仍显示 `Successfully received certificate`、`Successfully deployed certificate`，并且 `certbot renew --dry-run` 成功，可以先继续部署：

```text
ERROR: ld.so: object '/$LIB/libonion.so' from /etc/ld.so.preload cannot be preloaded
```

这通常是服务器系统级 `ld.so.preload` 残留配置导致的动态库加载警告，不代表证书申请失败。后续可单独检查 `/etc/ld.so.preload`，但不要在上线过程中直接删除或改动系统预加载配置。

验收标准：浏览器访问 `https://love.api.zhaoyisen.com.cn` 不出现证书警告。此时返回 502 可以接受，部署 API 后会恢复。

### 10.2 生成 TIMELINE_CURSOR_SECRET

在生产服务器执行：

```bash
openssl rand -hex 32
```

把输出复制到 `TIMELINE_CURSOR_SECRET`。不要每次发布都更换，否则已有分页游标会失效。

### 10.3 关键填写规则

- `SERVER_BIND_ADDRESS` 保持 `127.0.0.1`，不是域名；
- `COS_BUCKET` 填完整桶名，包括 APPID；
- `COS_REGION` 必须和桶控制台一致；
- Redis 没有用户名时 `REDIS_USERNAME=` 留空；
- Redis 启用 TLS 时填写 TLS 端口并设置 `REDIS_SSL=true`；
- 单机 Docker Redis 没有明确启用 TLS 时，填写 `REDIS_SSL=false`；
- 使用 `host.docker.internal` 访问同机 Docker MySQL/Redis 时，确认 API 服务已配置 `host-gateway`；
- 所有值一行一个，不要在等号两侧加空格；
- 为减少 `.env` 解析问题，MySQL/Redis 密码建议使用 24 位以上大小写字母、数字、下划线和短横线组合，不要包含空格、`#`、引号、反斜杠或 `$`；
- 不要给密码额外加引号；
- 不要把真实文件放在仓库目录。

验收标准：生产环境变量文件填写完整，文件不在 Git 仓库中。

## 17. 修改小程序生产 API 配置

打开：

```text
miniprogram/core/api-config.ts
```

改成：

```ts
export const API_CONFIG = {
  baseUrl: envVersion === "develop"
    ? "http://127.0.0.1:8080/api/v1"
    : "https://love.api.zhaoyisen.com.cn/api/v1",
  useRemoteApi: true,
  envVersion,
  stableDevIdentity: envVersion === "develop",
  clientVersion: "0.2.0",
  channel: "WECHAT_MINI"
};
```

真实 API 域名使用 `love.api.zhaoyisen.com.cn`。

这里的行为是：

- 微信开发者工具编译：使用本机 `127.0.0.1`；
- 上传后的体验版：`envVersion` 是 `trial`，使用生产 HTTPS；
- 正式版：`envVersion` 是 `release`，使用生产 HTTPS。

因此：

- 在开发者工具模拟器联调本机 Java 时，可以使用 `127.0.0.1`；
- 点击普通“预览”扫码时可能仍是 `develop`，不能依赖它测试生产接口；
- 测试生产接口请上传代码并设置为“体验版”。

修改后执行：

```powershell
cd D:\devlop\love_records
npm run validate
npm run typecheck
```

然后提交并再次走 `develop → main` 流程，确保微信上传的代码和 GitHub `main` 一致。

验收标准：生产 URL 已替换，`useRemoteApi: true`，检查通过并已合并到 `main`。

## 24. 最常见问题

### 24.1 手机提示 127.0.0.1 不在合法域名

原因：普通预览属于 `develop` 环境，代码使用本机地址。生产接口测试请使用“体验版”，体验版会使用 HTTPS 生产域名。

### 24.2 Jenkins 8080 端口冲突

Jenkins 必须改成 8081，API 保持 127.0.0.1:8080。

如果 Jenkins 是 Docker 容器，`docker ps` 中不能出现 `0.0.0.0:8080->8080/tcp`。先查看容器挂载和标签，确认它是否由 Compose 管理，再把宿主机端口改为 `8081`。改端口时必须保留 `/var/jenkins_home` 对应的数据卷或宿主机目录，避免丢失 Jenkins 配置。

### 24.3 Jenkins 提示不能执行 Docker

```bash
sudo usermod -aG docker jenkins
sudo systemctl restart jenkins
sudo -u jenkins docker version
```

### 24.4 API 容器不健康

```bash
sudo docker ps -a
sudo docker logs --tail 500 love-notes-api-1
```

优先检查 MySQL、Redis、微信 AppSecret、COS 桶名和地域。

### 24.5 媒体一直“安全处理中”

检查：

1. COS 桶是否绑定数据万象；
2. 是否完成服务角色授权；
3. COS 地域是否填写正确；
4. 主账号密钥是否有效；
5. 容器日志中是否有 `PROVIDER_UNAVAILABLE`。

### 24.6 域名 HTTPS 正常，但微信仍报非法域名

检查：

1. 微信公众平台填写的是 `https://love.api.zhaoyisen.com.cn`，没有 `/api/v1`；
2. COS 域名已分别加入 request、uploadFile、downloadFile；
3. 没有填写端口；
4. 保存后重新编译并重新上传体验版。
