# 媒体与记录管理端

管理端由现有 Spring Boot 服务提供，不需要独立部署前端。页面通过真实 API 查询数据库、检查 COS、创建任务，正式页面没有示例数据回退。

## 入口与配置

- 本地：`http://127.0.0.1:8080/api/v1/admin/`。
- 按当前生产域名配置，更新服务后入口为 `https://love.api.zhaoyisen.com.cn/api/v1/admin/`。这不是已经部署或连通的声明。
- 登录使用现有 `INTERNAL_OPERATION_TOKEN_HASH` 对应的**原始运维口令**，输入哈希本身不能登录。服务端仅保存 SHA-256，口令不要写进网页或 Git。
- 输入操作人名称用于审计标注；首版所有管理员共用一个权限级别，名称不构成独立身份验证。
- 使用 HTTPS。网页同源调用 `/api/v1/internal/admin/*`，不需要跨域配置。代理应转发正确的 Host 与 HTTPS 信息，并允许此管理路径。
- 会话 Cookie 为 HttpOnly、SameSite=Strict，默认闲置 20 分钟失效，可通过 `.env` 的 `ADMIN_SESSION_TIMEOUT` 调整。口令不写入 localStorage/sessionStorage；退出会注销会话。服务重启后需要重新登录。
- 未配置运维口令时管理登录关闭。生产登录接口复用现有限流，默认每 IP 每分钟最多 10 次尝试。
- 新增 Flyway `V22__media_admin.sql`。升级前按现有部署流程备份数据库；不需要人工改记录状态。
- 已使用隐藏功能后，回滚服务时必须保留 `admin_hidden` 过滤逻辑；不识别该标记的旧版本可能重新展示隐藏记录。不要直接回退到旧服务读取这些数据。

生产继续使用 `prod` 配置的 MySQL/COS。`dev`/`test` 的 LocalObjectStorage 是原有联调模拟存储，不代表真实文件检查或生成；不要用其检查结果判断生产文件是否丢失。

生产参数只维护 `/opt/love-notes/.env`：设置 `INTERNAL_OPERATION_TOKEN_HASH`、`ADMIN_MEDIA_WORKER_ENABLED` 和 `ADMIN_MEDIA_POLL_MS` 后，按[部署指南](Jenkins-Docker-Compose服务端部署指南.md)校验并重建 API 容器生效。Jenkins 不再读取旧 Secret file，也不会覆盖服务器配置。首次切换流水线前先迁移 `.env`、Compose 并配置 Jenkins 只读挂载，管理端仍随现有后端镜像发布。

## 日常使用

1. 搜索昵称或完整账号 UUID；重名时用 ID 区分。选择后只管理该账号自己发布的记录。
2. 初次进入点击“检查媒体”，不勾选记录时检查该账号全部记录的媒体；勾选时仅检查所选记录。
3. 在“媒体异常”中筛选原文件缺失、封面缺失、展示图缺失、检查失败等。未检查不是正常，网络/权限失败不是文件丢失。
4. 打开右侧详情，按素材查看原文件、展示文件和封面状态，预览原照片/视频。
5. 勾选记录后“重建封面”。确认页展示基于最近检查结果的已知可修复、待检查和跳过项；后台执行时再次读取实际状态，正常文件跳过。批次最多选择 500 条记录、包含 5000 个媒体，更多数据分批执行。
6. “任务记录”保存每个媒体的进度和结果，可重试失败项。任务由服务端定时处理，关闭网页不终止任务；进程重启后未完成项继续处理。
7. 单条或批量隐藏保留原文件、正文、评论、回应和原可见范围。双方时间线、记录相册、详情、回顾和相关信笺均不再展示，新的普通用户媒体授权被拒绝。
8. 切换“已隐藏”可恢复。恢复沿用原 status/visibility/couple_id，不触发再次发布通知，不更改为共同可见；回收站记录仍按原流程管理。

切换账号会清空所选记录与详情；操作带账号范围及记录版本，跨账号 ID、并发修改和过期版本会被服务端拒绝。隐藏与恢复也会保留操作记录。

## 文件与权限边界

- 只有 READY 且源文件可用的媒体允许重建。FAILED/BLOCKED/DELETED 不通过修复绕过安全处理或删除状态。
- 源照片/视频本身已经丢失时无法重建，应由管理员决定是否隐藏。
- 检查首先请求对象元数据；COS HEAD 的模糊 404 通过最多 1 字节的 GET 确认，区分对象缺失与桶/权限/网络错误。
- 新封面使用新的派生对象路径，以便小程序检测实际媒体变化；源文件不覆盖，正常的展示图/封面保留。新旧、部分生成的派生路径在请求生成前持久化纳入原媒体的删除清单，随回收站清理/账号注销一起删除。
- 隐藏是服务器内容展示控制，不是 COS 永久删除。此前已经签发的 URL 最长仍有原来的短期有效期；已下载文件无法从用户设备追回。在线小程序在下一次业务版本同步/返回页面或下拉后撤下内容。
- 检查结果是最近一次检查的快照，存储文件之后变化时需要重新检查。

## 后台参数与验证

### 重建失败的定位

列表缩略封面、详情展示图和上传原文件是独立的文件。照片在小程序列表中有封面，不代表展示图也存在；小程序还可能显示已下载的本地缓存。管理端检查的是存储端当前文件状态，结果保留最近一次检查的快照。

重建失败时，任务提示区分“封面生成失败”和“封面生成后的文件验证失败”。在发布包含诊断日志的后端版本后，重试一条失败素材，再在 Ubuntu 服务器查看：

```bash
sudo docker logs --since 10m love-notes-api-1 2>&1 | grep -E 'COS derivative regeneration failed|COS object check failed|Admin media rebuild failed' | tail -n 30
```

`Admin media rebuild failed` 包含素材 `asset`、任务 `task`、任务项 `item`、失败阶段 `GENERATE`/`VERIFY` 和生成文件的验证状态。腾讯云生成调用失败时，`COS derivative regeneration failed` 包含 `generation`（同一个任务项 ID）、分类、HTTP 状态、错误码和请求 ID，不输出原始异常消息、密钥或签名链接。根据真实错误码再检查权限、数据万象服务开通、格式或网络；不要仅凭旧版统一错误文案认定为权限问题。修改代码需要 Jenkins 构建并发布新镜像，单纯重建旧镜像不会获得新日志。

`MediaBucketUnBinded` 表示媒体处理服务尚未绑定，需要在腾讯云控制台对实际配置的存储桶开启媒体处理。`InvalidArgument` 会归类为 `REQUEST_PARAMETER`，日志额外提供 `parameterMessage`：只保留该错误码的参数说明，过滤配置密钥、URL、认证信息及控制字符，并限制长度。三条视频都报参数错误时，先查看此说明定位具体字段，不反复批量重试或凭猜测修改截图参数。这个字段不输出完整响应 XML，也不会将腾讯云原始异常返回普通用户。

视频封面通过实时截图接口获取 JPEG，再使用标准 COS `PutObject` 写入已登记的新封面路径，避免部分存储桶使用 `POST /snapshot` 时返回参数错误。读取端需要截图权限，写入端需要目标 `thumbnail/` 路径的 `cos:PutObject` 权限。返回内容须为 JPEG 且不超过 20 MiB；读取失败、空响应、非 JPEG 或超限时不上传。成功后仍由后台检查新文件，再更新记录引用；原视频不覆盖。只读诊断通过不代表保存权限已经验证，发布后仍需选一条记录验收实际重建。

默认开启工作器：`ADMIN_MEDIA_WORKER_ENABLED=true`，轮询间隔 `ADMIN_MEDIA_POLL_MS=1000`。任务逐个媒体执行，事务/行锁避免重复处理；生产实例无需浏览器保持打开。
