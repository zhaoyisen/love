# Q: 我只能用腾讯的oss吗？能不能自己搭建一个自己的存储？

## Answer

Expanded via graph vocabulary [object, storage, cos, local, processing]. Self-hosted storage is feasible. Current ObjectStorage interface centralizes upload credentials, signed reads, media derivatives, audit and deletion. Production CosObjectStorage still invokes Tencent STS/COS SDK, image/video/text auditing, image transforms and video snapshots; mini-program media-service.ts uploads through COS SDK and media-cache.ts checks COS q-key-time expiry. Migrating requires adapting uploads, access signatures/cache expiry, media derivatives and auditing inputs, plus copying original/display/thumbnail objects and preserving private access/deletion behavior. LocalObjectStorage is a dev/test stub returning local:// URLs, fabricated metadata and always-READY audit results, not a real disk-storage implementation. For personal small usage, authenticated server-disk storage is possible; for a general self-hosted object-store route evaluate an S3-compatible server such as SeaweedFS (official OSS repository verified). Thumbnailing can run on a separate worker using FFmpeg/image tools while content auditing remains an adapted third-party API. Self-hosting does not automatically improve latency or eliminate bandwidth, disk, backup and operations costs. No code edits or migration performed.
